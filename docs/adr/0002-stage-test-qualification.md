# 开发反馈先行，关键依赖等待正式测试资格

2026-11-01，用户确认 v3 每轮新增一个行为例子，经轻量判据核对与有效 Red 确认后驱动最小实现和重构；完整双轴测试审查放在关键契约检查点与最终验收。这样保留紧密的 TDD 反馈，接受开发期间尚未取得完整测试资格的局部结论；开发 Green、测试判据合格和产品正式验收通过必须分别记录。

普通开发流及关键契约自身的前置例子按 Green 推进，被该关键契约阻塞的消费者则等待相应测试资格与固定版本正式执行通过后才开工。检查点必须能在被阻塞的消费者尚未实现时运行，以免“下一例等审查、审查又等下一例”的循环；最终仍在交付的同一版本完成完整验收与代码审查。
