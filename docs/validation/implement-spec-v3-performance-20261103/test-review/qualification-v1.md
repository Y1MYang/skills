## Material gaps and smallest next observations

These are **confirmed test-set omissions**, leaving the affected behavior evidence missing/unverified; they are not confirmed product defects. All test changes belong to the independent Test author; the separate Runner supplies results. No business decision is missing for these public guarantees. The root accepted this bounded packet for repair; extra parser/collision/platform permutations mentioned in axis limitations are not additional repair demands.

**Q1 — New execute envelope validation has no rejection example.** `test_cycle_performance.py:61–75` only emits valid envelopes; E03/E09 are post-binding conflicts, E16 is a reserved-ID conflict. Contract §3 requires malformed envelope rejection before a new preparation commits. A helper accepting extra fields could pass all 37 cases. Add one otherwise valid request with an unknown outer field, a target-owned marker, unchanged inspect/accounting and a repaired same-ID retry. This is a representative boundary check, not a request for every input permutation.

**Q2 — The execute timeout-record path is unobserved.** The standalone runner timeout tests do not prove that `execute` records an actual timeout receipt and returns receipt-recording success with `outcome:"timeout"`, `exit_code:null`, settled reservation and retained failure. One real bounded timeout case establishes that wrapper path without a benchmark ratio.

Correction 1: the initial report also requested E06 first-response assertions after its `TerminateProcess`. That request is withdrawn. The public contract does not require the claim controller to be a different OS process from outer execute; killing it may kill the very process expected to report. Requiring a surviving JSON response would add a process-architecture constraint. Existing `leave_bound_formal_preparation_before_launch` at lines 203–214 already requires initial execute exit 2/ok:false, no target launch/receipt and retained pending preparation, and §3 expressly permits the applicable runner error. E08 subsequently proves matching receipt adoption. E06 remains valid killed-controller replay/recovery evidence and stays unchanged. A no-claim replay remains a stated limitation, not a new repair demand.

**Q3 — Entry-time tampering does not establish the post-execution fresh audit.** H01 at lines 708–739 modifies evidence before each command begins. A helper that audits once before waiting and trusts that old audit after external execution could pass H01 and the current concurrency cases. Reuse E05's acknowledged waiting-target boundary: corrupt an already adopted evidence file after target acknowledgement, release the target, and require the helper to reject the record transition while preserving the durable pending prefix. This is a deterministic public side-effect scenario. No inter-item race, arbitrary sleep or private product hook is requested. The suite's lack of a deterministic intra-batch audit observation remains a stated limitation.

**Q4 — One-edge barriers do not establish repeated closure or accepted gate invalidation.** S09/S10 at lines 958–1006 each exercise one edge, and they reject the edit before invalidation can occur. The contract explicitly requires repeated ordinary/gate closure and revocation of affected proof even without file-byte changes. Add one mixed two-edge dependency scenario with only the terminal consumer pending, so stopping after one propagation step would wrongly admit the edit. Add one accepted-edit scenario that preserves unlisted completion history but demonstrably rejects reuse of an affected old gate proof/release after the named prerequisite has been validly refreshed, at unchanged bytes. Existing directly listed final invalidation remains credited; it does not cover an affected unlisted gate.
